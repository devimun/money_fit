## 3. 완료 이식 작업 (T1–T7)

아래 task는 당시 `부분 이식`/`미이식`이었던 행을 닫았다. 완료 판정은 코드
존재만으로 하지 않고 **source 성공 지점 + 실패 시 미발행 + 회귀 테스트**의
근거를 각 matrix 행에 연결했다. T1–T7 범위에서 남은 non-adapted 상태는
명시적 범위 제외인 C6뿐이다.

| Task | 소유 범위 | 닫아야 하는 matrix | 상세 완료 조건 |

## 4. 최종 acceptance gate

1. T1–T7로 닫힌 행은 위 target 경로와 테스트 근거를 유지한다. 이후 변경은
   source의 성공 지점과 실패 시 미발행/실패 격리 계약을 다시 검증해야 한다.
2. `C6` app-open은 **명시적 제외**로 남긴다. "완전 이식"에 app-open
   lifecycle까지 포함시키려면 사용자 승인 뒤 T4와 분리된 구현·test plan을
   새로 선언한다.
3. source 최종 blob이 동일한 Supabase 9 files와 metadata validator는 미래
   변경에서 의도 없이 수정하지 않는다. 변경이 필요하면 이 표에 migration
   compatibility/operational review를 추가한다.
4. 최종에는 `flutter pub get`, `flutter gen-l10n`, format, analyze, full
   Flutter test, Deno delivery test, metadata validator, Fastfile Ruby syntax,
   `git diff --check`를 실행한다.
